# Filesystem reader for approved car readiness reports

`createCarFileReportRegistry` implements `CarReadinessReportReader` with real,
bounded filesystem reads. It is not imported by production runtime or routes.
It neither approves an index nor issues reports. An external authorized review
must establish the directory, index hash, report/artifact provenance and signer
trust before this adapter is used with actual evidence.

## Trusted configuration and layout

The factory accepts a trusted absolute `directory`, `approvedIndexSha256` and an
optional server clock. No HTTP input, URL, credential or caller-supplied filename
is used. Missing configuration fails closed. Use a canonical private directory
outside the public/static tree. Directory ownership, permissions and publishing
are deployment responsibilities; this is not a sandbox against a hostile local
administrator swapping parent directories.

The fixed layout is:

```text
index.json
reports/<check-id>.json
artifacts/<artifact-sha256>.json
```

The index contains exactly `version: car-report-registry-v1`, positive integer
`approvedAt` / `expiresAt` epoch milliseconds, and `reports`. There must be exactly
one entry for each of the eleven existing readiness check IDs. Each entry has
only `id`, `reportSha256`, and `artifactSha256`. The report pin hashes the exact
UTF-8 bytes of the nested `reportJson` string, matching the envelope protocol.
No real approved index is supplied or generated by this implementation.

Each report file is the existing `{ reportJson, signature, issuerKeyId }` wire
object. The reader checks its exact shape, canonical base64 signature size,
bounded UTF-8 report bytes and report/artifact pins. The report's ID, issuer and
artifact hash must agree with its file/index. The actual artifact is read and
hashed, but its bytes are never returned. A matching artifact hash is not proof
that an experiment ran or passed; the authorized reviewer must inspect it.

The existing readiness envelope verifies the trusted Ed25519 key, full report
schema, candidate/environment/offer, report expiry and approved manifest pins.
Successful file reading alone is not readiness or sales authorization.

## Bounded reads and withdrawal

Index/report-wrapper/artifact limits are 16,384 / 131,072 / 2,097,152 bytes.
Regular files, no symbolic-link leaves, canonical directories and opened-file
identity are checked. A stream reads at most limit+1 bytes to detect growth;
this avoids allocating an entire unexpectedly large file. Invalid UTF-8 JSON,
bad pins, non-files, missing files and I/O errors return one fixed error without
paths or data. Filesystem handles are closed on success and failure.

The request AbortSignal is passed into
[FileHandle.createReadStream](https://nodejs.org/api/fs.html#filehandlecreatereadstreamoptions).
Cancellation destroys that stream; the envelope's separate ten-second report
deadline also fences late results. A pending metadata/open operation still
depends on filesystem/OS completion; no OS-level cancellation guarantee is made.

The index is read afresh for every report and reread after artifact I/O. Replacing,
withdrawing or editing it makes its old pin fail. Approval expiry is checked
before and after reading. Revocation after a reader returns cannot retroactively
invalidate that returned object: a production rollout must drain/invalidate
in-flight readiness operations when changing trust or approvals. Atomic index
publication, access control and revocation distribution are not implemented here.
No cache, writer, signer or network storage service is added.

## Local verification

`scripts/check-car-purchase-file-report-registry.mjs`: 50 checks, 98 real file
opens and 98 closes; actual stream cancellation, index withdrawal during artifact
I/O, expiry, concurrent request isolation, symlink root rejection and tampered /
oversized input. Fixtures and ephemeral signatures are explicitly synthetic;
the minimal fixture descriptors are not valid executed readiness reports.
Temporary fixture files remain outside the source/operations workspaces; no
cleanup or deletion occurs. Strict scoped ES2017 TypeScript and two-file lint pass.

The follow-up `scripts/check-car-purchase-file-envelope.mjs` verifies real file
reads composed with the actual envelope, Node Ed25519 verification and catalog
validation. Its 25 checks use twelve complete sets of eleven synthetic signed
descriptors, 60 report reads, four mock catalog queries and one fixture bootstrap;
229 file opens are matched by 229 closes. It covers wrong signatures, mismatched
environment/offer, expired reports, artifact tampering, index withdrawal between
calls and during the report phase, catalog drift and deadline propagation into
the actual file reader. Normal results retain `salesAuthorized: false`.

Actual reviewed artifacts, remote registry provisioning, driver/DB acceptance,
UI/PWA and production wiring remain NOT_RUN. This assembled local test does not
prove real database execution or authorized approval. The next release decision
still needs actual target/driver acceptance and approval/revocation distribution;
do not add more format layers or repeat unrelated completed checks.
